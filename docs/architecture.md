# 현재 인식·제어 구조

기준 계획은 [로드맵](roadmap.md)이다. 기존의 굳기 분류 중심 목표를 대신해,
분변 중심 검출과 청소 영역 추정의 실기 검증을 먼저 진행한다.

## 구현된 경로

1. Nicla QVGA RGB 프레임 → 96×96 분변 FOMO 모델.
2. 분변 중심 → 112×112 ROI → LAB blob 선택 → 8 px 여유 폭 bbox.
3. 최근 5프레임 중 3프레임에서 근처의 같은 클래스가 검출되면 표시.
4. 기존 NV01 TCP 스트림으로 JPEG, det[], ToF 거리, 파이프라인 상태를 노트북 뷰어에 송출.

현재 모델은 background/stool 두 클래스다. 소변 ROI 설정은 미래 확장용이며,
현재 모델이 소변이나 물변을 검출한다는 뜻이 아니다.
ROI와 여유 폭은 픽셀 단위 초기값이며 물리적인 롤러 청소 범위를 보장하지 않는다.
상세 설정·스위치·검증 게이트는 [TinyML + ROI](tinyml_roi.md)를 따른다.

## 연결되지 않은 구성

| 구성 | 상태와 다음 조건 |
|---|---|
| 모바일 웹 UI | 시뮬레이션. 로컬 브리지의 영상·상태·명령 API 필요 |
| 차량 제어 | vehicle_send()는 명령을 기록하는 stub. UART 출력 없음 |
| 자율 정지 | 검출에서 정지로 연결하는 판단 로직 미구현 |
| 소변 영역 | LED 차분 실험 통과 후 통합. 현재 차분 분석 도구만 존재 |
| 굳기 분류 | MobileNetV2 + CORAL은 보류된 후속 아이디어 |
| ToF 특징 | 원시 거리 송출만 존재. 객체별 높이·분류 입력으로 사용하지 않음 |

모바일 UI의 우선순위, 회전 거리, 경로, 롤러 동작, 비상정지는 실제 제어 결과가 아니다.

## 실기 검증 조건

- 모델·라벨·임계값을 같은 버전으로 배포한다. 기준 모델 임계값은 0.60.
- auto는 모델 로드 실패 시 color_demo로 폴백한다. 실제 모델 검증에는
  DETECTOR_MODE="tinyml_roi"를 사용해 실패를 드러낸다.
- 실제 FPS, RAM, 중심 오차, ROI 커버리지, 오탐률과 시간 합의 지연을 측정한다.
- 화면에서 겹치는/빠르게 움직이는 물체에 대한 합의 필터 동작을 별도로 확인한다.
- homography와 실제 롤러 치수를 이용한 주행 좌표 변환을 구현하기 전에는
  픽셀 bbox나 UI의 예시 거리를 차량 이동 명령으로 취급하지 않는다.

## 후속 액체 경로

LED 켬/끔 차분 → 액체 후보 영역 → 필요 시 FOMO ROI와 결합한다.
주행 중 두 프레임의 어긋남은 감속·정지 후 확인을 먼저 시도한다.
차분 분리도와 마른 반사체 오탐 게이트를 통과하지 못하면 소변 ROI
세그멘테이션을 검토한다. 소변 학습·라벨·실기 검증 없이 클래스만 추가하지 않는다.
