# 인식 구조 (분변 + 오줌)

1단계 결과에 따라 바뀔 수 있는 **목표 구조**. 굵은 글씨는 아직 1단계 판정을 기다리는 부분.

```
            LED 켬/끔 교대 촬영 (alt 모드)
                     │
        ┌────────────┴─────────────┐
        ▼                          ▼
   LED 켬 프레임 (RGB)        켬 − 끔 차분 (반사)
        │                          │
        ▼                          ▼
 ┌──────────────┐          ┌───────────────┐
 │ 모델 A: FOMO │          │ 액체 후보 검출 │  고전 처리: 정규화 차분 → 임계값
 │ 분변 / 액체  │◄─ 보조 ──│ (반사 덩어리)  │  → 덩어리(blob) → 면적
 └──────┬───────┘   입력   └───────┬───────┘
        │ 분변                     │ 액체
        ▼                          ▼
  128×128 크롭               색으로 구분 (b* 노란색 vs 갈색)
  + ToF 높이, 면적           → 오줌 / 물변
        │
        ▼
 ┌────────────────────┐
 │ 모델 B: 굳기 분류  │  MobileNetV2 α=0.35 + CORAL 순서형
 │ 단단/정상/무름/물변 │  + ToF·면적 특징
 └─────────┬──────────┘
           ▼
     검출 결과 → 송출 헤더 det[] (cls: stool / urine / liquid_stool)
           │
           ▼
     자율 정지 판단 (보드 안) · 노트북 표시
```

## 클래스

| 클래스 | 주 단서 | 보조 단서 |
|---|---|---|
| `stool` | 형태·색 (RGB) | ToF 높이, 높이÷면적 |
| `urine` | **켬−끔 차분의 반사 덩어리** | 노란색(b*), 높이 0 |
| `liquid_stool` (물변) | 갈색 + 반사 | 모델 B 등급 3과 교차 확인 |

## 액체 분기를 FOMO에 넣는 방법 (1-6 결과 보고 선택)

1. **분리형 (먼저 시도)**: 차분 영상에 고전 처리(임계값 → 덩어리)만 적용. 학습 없음, 계산량 거의 0. 1-6 d'가 충분히 크면 이걸로 충분.
2. **보조 입력형**: FOMO 입력을 RGB 3채널 → RGB + 차분 4채널로. 사전학습 가중치는 첫 층만 새로 학습. 바닥 무늬에 속는 경우가 많을 때.
3. **단일 RGB형**: 차분 없이 LED 켬 프레임만으로 학습. 주변 조명에 약해서 1-6에서 조명 강건성이 확인될 때만.

## 주행 중 차분의 문제와 대책

LED를 교대로 켜면 한 쌍의 두 프레임 사이 시간(약 100~200 ms) 동안 차량이 움직여 모든 물체 테두리가 차분 영상에 뜬다.

| 대책 | 방법 | 비용 |
|---|---|---|
| 저속·정지 판단 | 액체 후보가 보이면 감속 → 정지 상태에서 확인 촬영 | 동작 로직만 추가. **1순위** |
| 정렬 보정 | 바닥 호모그래피(1-2 결과)와 주행 속도로 이전 프레임을 이동시켜 뺌 | 보드 계산 부담, 바퀴 속도 정보 필요 |
| 빠른 교대 | 해상도를 낮춰(QQVGA) 프레임 간격 단축 | 화질 저하 |

## 보드 메모리 예산 (추정, 4단계에서 실측)

| 항목 | 크기 |
|---|---|
| QVGA 프레임 2장 (켬·끔) | 약 300 KB |
| 모델 A (FOMO, int8) | 약 100 KB + 작업 메모리 |
| 모델 B (int8) | 약 500 KB |
| 합계 | 1 MB RAM에 빠듯함 → 차분은 그레이스케일 1채널로 저장, 모델 B 입력 96×96 축소를 대안으로 |
